## Trang này dành cho ai?

Lộ trình này phù hợp với người đã có Java cơ bản và muốn hiểu cách một GraphQL request đi qua ứng dụng Spring Boot. Bạn không cần biết GraphQL trước. Nếu chưa quen với schema, operation hoặc execution result, hãy đọc nhóm [Nền tảng](/docs/nen-tang) trước khi bắt đầu.

## Điều kiện cần có

Khi thực hành trên một backend thật, hãy chuẩn bị:

- **JDK 17** và một terminal. Các bài dùng dòng Spring Boot 3.x, trong đó JDK 17 là mốc chính.
- Một project dùng Maven và Maven wrapper; các bài có đề cập lựa chọn Gradle ở nơi phù hợp.
- Trình duyệt để mở Spring Initializr và GraphiQL.
- Kết nối mạng cho lần tạo project hoặc lần build đầu tiên, khi Maven cần tải dependency.

Nếu chỉ đọc để nắm flow, bạn có thể đi qua các bài mà chưa cần cài backend. Khi chạy lệnh, hãy đối chiếu version Spring Boot, port và endpoint trong project thực tế với giả định của từng bài.

## Mục tiêu đầu ra

Sau khi hoàn thành nhóm này, bạn có thể:

- Tạo và kiểm tra một project Spring Boot tối thiểu.
- Thêm Spring for GraphQL, đặt schema trên classpath và cấu hình HTTP endpoint local.
- Viết schema SDL với query root, scalar, object và list.
- Nối một query với resolver, gửi operation và đọc `data` cùng `errors` trong execution result.
- Dùng GraphiQL để khám phá schema, chạy query, truyền variables và headers.
- Gửi lại cùng request bằng `curl` hoặc Postman để tạo quy trình kiểm thử lặp lại được.

## Thứ tự học đề xuất

Đi theo thứ tự sidebar từ trên xuống dưới. Mỗi chặng tạo đầu vào cho chặng kế tiếp:

1. **Khởi tạo project** để có bộ khung Spring Boot và kiểm tra JDK, Maven wrapper.
2. **Thêm dependency và cấu hình** để ứng dụng có GraphQL runtime, schema location và HTTP endpoint.
3. **Tạo schema đầu tiên** để định nghĩa contract mà client được phép yêu cầu.
4. **Viết query đầu tiên** để nối field trong schema với resolver và dữ liệu trả về.
5. **Khám phá API bằng GraphiQL** để đọc schema, chạy operation và phân loại lỗi.
6. **Kiểm thử request bằng curl/Postman** để chuyển request đã chạy sang quy trình kiểm tra ngoài giao diện.

## Cách dùng các bài đã hoàn thiện

Đọc sáu bài đã hoàn thiện theo thứ tự trên và giữ lại kết quả của mỗi chặng trong project thực hành:

1. Sau bài khởi tạo, xác nhận project có thể build test trước khi chuyển sang GraphQL.
2. Sau bài cấu hình, kiểm tra dependency, vị trí schema và URL endpoint có thống nhất.
3. Sau bài schema, xem SDL là contract độc lập với dữ liệu và resolver.
4. Sau bài query, chạy một field nhỏ trước rồi mới mở rộng sang object hoặc list.
5. Sau bài GraphiQL, đối chiếu schema, operation và execution result; đặc biệt phân biệt lỗi validation, resolver và HTTP.
6. Sau bài curl/Postman, gửi lại cùng operation qua HTTP client và lưu request hoặc assertion để kiểm tra lặp lại.

Ở chặng cuối, dùng bài [Kiểm thử request bằng curl/Postman](/docs/bat-dau/kiem-thu-request-curl-postman) để chuyển operation đã chạy trong GraphiQL thành smoke test có thể lặp lại. Như vậy, nhóm bao phủ cả đường đi trên UI lẫn kiểm tra request qua HTTP client.
